# إلكترو POS (Electro POS)

نظام نقطة بيع كامل لمتجر أجهزة كهربائية — شاشة كاشير، مخزون، عملاء،
**تقسيط**، **تسجيل ضمان بالرقم التسلسلي**، وتقارير مبيعات. الواجهة بالكامل
باللغة العربية (RTL).

مبني على **Django + SQLite** في الخلفية، و**HTML/CSS/JS** عادي في الواجهة.

## التصميم

الواجهة مبنية على تصميم زجاجي داكن (glassmorphism) بتدرج كحلي إلى بنفسجي،
مأخوذ من ملفات التصميم التي تم تزويدنا بها (`index.html` / `style.css` / `main.js`
الأصلية)، مع تعديل واحد جوهري: التصميم الأصلي كان "تبويبات" (tabs) تتنقل
بجافاسكريبت داخل صفحة واحدة. بما أن هذا نظام حقيقي متعدد الصفحات (كل صفحة
لها رابط خاص بها، سجل تصفح، وإمكانية عمل رابط مباشر لها)، تم تحويل شريط
التبويبات الجانبي إلى **قائمة تنقل حقيقية بين صفحات فعلية**، مع الحفاظ على
نفس الشكل والألوان والحركة تماماً كما في التصميم الأصلي. كل صفحة أخرى
(المنتجات، المخزون، العملاء، الضمانات، التقارير) استخدمت نفس المكوّنات
(البطاقات الزجاجية، الشارات، أشرطة التقدّم، شبكة الإحصائيات) حتى تبقى
متسقة تماماً مع تصميم لوحة التحكم الأصلي.

## المحتويات

| القسم | الوظيفة |
|---|---|
| **شاشة الكاشير** (`/cashier/`) | ابحث عن منتج أو اضغط عليه، أضف للسلة، اختر الدفع نقدي أو تقسيط، سجّل رقماً تسلسلياً إن وُجد، أتمم البيع. المخزون يُخصم تلقائياً ضمن معاملة واحدة متكاملة. |
| **المنتجات** (`/manage/products/`) | إضافة/تعديل/حذف المنتجات: الاسم، الباركود، السعر، سعر التكلفة، المخزون، حد التنبيه، مدة الضمان. |
| **المخزون** (`/manage/inventory/`) | حالة المخزون لكل صنف، مع نموذج إعادة تعبئة سريع. |
| **العملاء** (`/manage/customers/`) | بيانات العملاء، سجل المشتريات، وخطط الأقساط مع رصيد متجدد. |
| **الضمانات** (`/manage/warranties/`) | كل رقم تسلسلي يُدخل عند البيع يُسجَّل تلقائياً بتاريخ بداية ونهاية الضمان. |
| **التقارير** (`/manage/reports/`) | الإيرادات، الربح التقديري (سعر البيع − سعر التكلفة)، الأصناف الأكثر مبيعاً، وحركة الأموال (نقدي مقابل تقسيط) يومياً. |
| **الفواتير** (`/invoice/<id>/`) | فاتورة قابلة للطباعة لكل عملية بيع. |
| **التنبيهات** (`/manage/alerts/`) | أقساط العملاء وأرباح المستثمرين المستحقة قريباً، في مكان واحد. |
| **المستثمرون** (`/manage/investors/`) | رأس مال كل مستثمر، نسبة ملكيته الفعلية، الإضافة/السحب، ودفع الأرباح المستحقة. |
| **توزيعات الأرباح** (`/manage/distributions/`) | يحسب صافي الربح/الخسارة لفترة (إيرادات − تكلفة بضاعة − مصروفات) ويوزّعه على المستثمرين حسب نسبة الملكية. |
| **المصروفات** (`/manage/expenses/`) | رواتب، إيجار، كهرباء، وأي تكلفة تشغيلية — تُخصم من الأرباح قبل توزيعها. |
| **لوحة تحكم Django** (`/django-admin/`) | وصول اختياري لمن لديه صلاحية مدير عام على كل الجداول مباشرة. |

## إدارة المستثمرين (تفصيل)

هذا القسم مبني حسب مبدأ واحد صارم: **المستثمر لا يرتبط بأي فاتورة بيع مباشرة**.
السلسلة دائماً:

```
إيرادات المبيعات
   ↓ ناقص تكلفة البضاعة المباعة (COGS)
= إجمالي الربح
   ↓ ناقص المصروفات التشغيلية (رواتب، إيجار، كهرباء، مواصلات، صيانة، ضرائب...)
= صافي الربح أو الخسارة
   ↓ يُقسَّم على المستثمرين حسب نسبة ملكيتهم في رأس المال
```

- **نسبة الملكية محسوبة تلقائياً** من (رأس مال المستثمر ÷ إجمالي رأس المال النشط) — تتحدّث
  فوراً كلما أضاف أو سحب أحد المستثمرين، دون الحاجة لتعديلها يدوياً.
- **إنشاء توزيع أرباح** (`/manage/distributions/new/`) يعرض معاينة كاملة للحساب قبل أي
  تأكيد: الإيرادات، تكلفة البضاعة، إجمالي الربح، المصروفات، وصافي الربح/الخسارة، مع نصيب
  كل مستثمر تقديرياً — التأكيد فقط يُنفّذ العملية فعلياً.
- **عند الخسارة**، النظام يطلب اختيار سياسة واحدة من ثلاث (تماماً كما هو متعارف عليه في
  العقود): تُخصم من رأس مال كل مستثمر، أو تُسجَّل فقط دون خصم لتُعوَّض من أرباح لاحقة، أو
  يتحمّلها صاحب المشروع بالكامل دون أي أثر على المستثمرين.
- **الأرباح لا تُضاف تلقائياً لرأس المال** — تتراكم في "أرباح مستحقة" منفصلة، تُدفع للمستثمر
  عند الطلب عبر زر مخصص في ملفه الشخصي، وتُسجَّل كحركة "دفع أرباح" في سجله.
- **سجل حركات كامل** لكل مستثمر: استثمار أولي، إضافة، سحب، ربح، خسارة، دفع أرباح — بالتاريخ
  والمبلغ والرصيد بعد كل حركة.
- **تنبيهات موعد الدفع**: كل مستثمر له طريقة توزيع مفضّلة (شهري/كل 3 أشهر/كل 6 أشهر/سنوي)،
  والنظام يحسب موعد الدفعة القادمة تلقائياً ويُنبّه قبل 5 أيام من الاستحقاق — بنفس أسلوب
  تنبيهات أقساط العملاء، ومعروضة معاً في صفحة "التنبيهات".

## التشغيل

```bash
# 1. تثبيت المتطلبات
pip install -r requirements.txt

# 2. تطبيق الترحيلات (تُنشئ الجداول وتزرع بيانات تجريبية بالعربية)
python manage.py migrate

# 3. (اختياري) إنشاء مستخدم مدير لاستخدام /django-admin/
python manage.py createsuperuser

# 4. تشغيل الخادم
python manage.py runserver 0.0.0.0:8000

# 5. افتح في المتصفح
#    شاشة الكاشير: http://127.0.0.1:8000/cashier/
#    لوحة التحكم: http://127.0.0.1:8000/manage/
```

## ملاحظات قبل التشغيل الفعلي في المتجر

- لا توجد حالياً شاشة تسجيل دخول — أي شخص على نفس الشبكة يمكنه الوصول لكل
  الصفحات بما فيها لوحة الإدارة. أضف `@login_required` على واجهات `/manage/`
  قبل الاستخدام الفعلي (حزمة `django.contrib.auth` مُفعّلة بالفعل).
- غيّر `SECRET_KEY` في `config/settings.py` وعطّل `DEBUG` قبل النشر الفعلي،
  وحدّد `ALLOWED_HOSTS` بدلاً من `['*']`.
- SQLite مناسب لكاشير واحد؛ لأكثر من فرع يشتركون في نفس قاعدة البيانات
  لحظياً، انتقل إلى PostgreSQL أو MySQL في إعدادات `DATABASES`.
- مربّع البحث في شاشة الكاشير يقرأ من حقل الباركود مباشرة، لذا أغلب قارئات
  الباركود (USB/بلوتوث) تعمل مباشرة دون أي كود إضافي.
